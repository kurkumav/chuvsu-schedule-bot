# Бесплатный запуск на Cloudflare Workers

Версия для Cloudflare находится в `cloudflare/`. Она использует JavaScript, Telegram webhook, D1 для подписок и подгрупп, Cron для ежедневной отправки. Python-версия в корне продолжает работать на компьютере или Bothost.

Исходный бот [@dsfgfdfbot](https://t.me/dsfgfdfbot) уже перенесён на Cloudflare Free; ответ кнопки «Расписание на сегодня» проверен в Telegram. Локальные настройки подгрупп и подписок перенесены в D1. Worker: `https://chuvsu-schedule-bot.chuvsu-schedule-worker.workers.dev`, публичная проверка `/health`. Следующие шаги нужны для повторного развёртывания или настройки другого аккаунта.

Кнопки, учёт учебных недель, подгрупп и замен сохранены. Компьютер после переноса можно выключать. Домен покупать не нужно: используется адрес `workers.dev`.

Сайт ЧувГУ отдаёт неполную цепочку HTTPS-сертификата, поэтому прямой запрос из Cloudflare сейчас получает 526. Бот сначала пробует сайт, а при этой ошибке читает публичную копию из ветки `schedule-cache` этого репозитория. GitHub Actions обновляет её примерно каждые 15 минут. В ответе бота видно время копии; копии старше трёх часов отклоняются. Изменения на сайте могут появляться с задержкой, запуск Actions иногда задерживается. При ошибке разбора сайта резервная копия не подменяет результат.

Actions использует стандартный бесплатный Linux runner публичного репозитория ([тарифы GitHub](https://docs.github.com/en/billing/concepts/product-billing/github-actions)). Он скачивает только общедоступное расписание и публикует HTML без скриптов. Telegram-токена, Cloudflare-секретов и базы подписчиков в Actions нет. В `cloudflare/certs/` лежит публичный промежуточный сертификат GlobalSign, проверенный по доверенному корню; HTTPS, имя сервера и срок сертификата проверяются полностью.

## Тариф

Используй **Workers Free** и бесплатный **D1**. Не включай Workers Paid. По [тарифам Workers](https://developers.cloudflare.com/workers/platform/pricing/) Free включает 100 000 запросов в сутки; [D1 Free](https://developers.cloudflare.com/d1/platform/pricing/) — 5 млн прочитанных и 100 000 записанных строк в сутки, 5 ГБ хранения. При исчерпании бесплатных лимитов запросы перестают работать до сброса лимита; эта инструкция не подключает платный тариф.

У Free есть [ограничение CPU 10 мс](https://developers.cloudflare.com/workers/platform/limits/), поэтому здесь нет Python-интерпретатора и тяжёлых библиотек разбора HTML. Используется встроенный HTMLRewriter и двухминутный кеш в D1. Это небольшая версия для личного бота/группы; фактический CPU после публикации проверяется в Metrics. Рассылка обрабатывает до пяти подписчиков за один запуск Cron, следующие получают сообщение через пять минут. Для одного пользователя обычное время — 07:00 по Москве; точное время доставки зависит от Cloudflare и Telegram.

## Публикация с компьютера

Нужен Node.js 22 или новее и аккаунт Cloudflare. Открой терминал в папке `cloudflare`:

```sh
npm ci
npm test
npx wrangler login --scopes account:read user:read workers_scripts:write d1:write
```

В открывшемся браузере войди в свой Cloudflare и разреши Wrangler управлять Workers и D1. Логин и пароль в код не добавляются.

Создай базу:

```sh
npx wrangler d1 create chuvsu-schedule-bot
```

Команда выведет `database_id`. В `cloudflare/wrangler.jsonc` замени текущий UUID этим значением при установке в другой аккаунт. В исходном аккаунте база уже создана, повторно создавать её не нужно. UUID можно посмотреть в панели Cloudflare или `npx wrangler d1 list`.

```sh
npx wrangler d1 migrations apply chuvsu-schedule-bot --remote
npm run deploy
```

Сохрани адрес вида `https://chuvsu-schedule-bot.ТВОЙ-ПОДДОМЕН.workers.dev` из результата публикации.

Скрипты умеют читать токен из существующего `../.env` Python-бота. Если такого файла нет, скопируй `.dev.vars.example` в `.dev.vars` и впиши `BOT_TOKEN` и случайный `WEBHOOK_SECRET` длиной минимум 32 символа. Эти файлы исключены из Git. Не вставляй токен в браузерный URL или командную строку.

```sh
npm run secrets
```

Если токен уже есть в `../.env`, скрипт сам создаёт случайный `WEBHOOK_SECRET` и сохраняет локальные настройки в игнорируемом `.dev.vars`. Он также заменяет пример секрета из `.dev.vars.example` новым случайным значением. Затем передаёт оба секрета в Cloudflare через стандартный ввод Wrangler. В публичном репозитории их нет. Уже заданный секрет сохраняется, чтобы обновление не нарушило действующий webhook.

Проверь `https://ТВОЙ-АДРЕС.workers.dev/health`: должно быть `{"ok":true}`. Этот адрес не показывает сообщения, подписчиков или секреты.

**Теперь останови локальный Python-бот**, чтобы он больше не выполнял long polling и рассылку. Затем подключи Telegram, подставив сохранённый адрес:

```sh
npm run webhook -- https://chuvsu-schedule-bot.ТВОЙ-ПОДДОМЕН.workers.dev
npm run webhook -- status
```

Скрипт проверяет готовность Worker и загрузку актуального расписания до переключения Telegram, сохраняет очередь обновлений и проверяет установленный webhook. Проверка выполняется через `/check` с секретным заголовком: без секрета этот адрес возвращает 403. Если расписание недоступно, скрипт оставит прежний webhook и сообщит о сбое. Открой своего бота и нажми `/start`, затем «Расписание на сегодня».

## Рассылка и настройки

В `wrangler.jsonc` заданы `GROUP_ID=8075`, `BOT_TIMEZONE=Europe/Moscow`, `DAILY_TIME=07:00`. Для закрытого личного бота укажи свой числовой Telegram ID в `ALLOWED_USER_IDS`; можно несколько через запятую. После изменения конфигурации выполни `npm run deploy`.

Cron `*/5 * * * *` проверяет подписки каждые пять минут. Все [Cron Cloudflare работают по UTC](https://developers.cloudflare.com/workers/configuration/cron-triggers/), а код сравнивает время в выбранном часовом поясе. До 07:00 он ничего не отправляет. После успешной отправки дата сохраняется в D1. При сбое сайта или Telegram доставка повторяется через пять минут или позже, если Telegram потребовал более долгую паузу. Рассылка включается только кнопкой или `/subscribe`. Пропущенные прошлые дни не отправляются.

Cloudflare может применять новый Cron до 15 минут после публикации. Подписки и выбранные подгруппы Python-версии сами в D1 не переносятся: выбери подгруппу и включи рассылку заново. Если нужна миграция, старые данные находятся в локальном `data/bot.sqlite3`; не публикуй эту базу.

Webhook проверяет секретный заголовок Telegram. Повтор одного `update_id` и параллельные запуски Cron защищены атомарными блокировками в D1. После обычного повторного запроса или перезапуска уже подтверждённое сообщение не отправляется ещё раз. Если Telegram принял сообщение, но подтверждение потерялось, повтор возможен — Bot API не предоставляет ключ идемпотентности для `sendMessage`.

## Обновление и возврат на компьютер

Для новой версии кода: `git pull`, затем в `cloudflare` — `npm ci`, `npm test`, `npm run deploy`. Повторно подключать webhook не нужно, если адрес и секрет остались прежними.

Для возврата к Python:

```sh
npm run webhook -- disable
```

После этого запусти `start.bat`. Чтобы облачная рассылка тоже прекратилась, удали Cron в Settings → Triggers своего Worker или удали Worker. Python и Worker используют разные базы подписок.

Тесты запускают настоящий локальный runtime Cloudflare (`workerd` через Miniflare), проверяют D1, гостевой вход, кнопки, недели, замены, секрет webhook, повторы и рассылку. Telegram и сайт в автоматических тестах заменены контролируемыми ответами; реальные сообщения тесты не отправляют.

`npm run check` проверяет настоящий сайт без токена Telegram. Нужен Node.js **22.19+**: HTTPS этого локального диагностического скрипта проверяется через системное хранилище сертификатов, а разбор HTML и кеш выполняются в workerd/D1. `node scripts/snapshot.mjs` отдельно проверяет загрузку с публичным промежуточным сертификатом, без зависимости от системного поиска сертификатов Windows. Проверка TLS в рабочем коде остаётся включённой.

## Обновление публичной копии

Workflow `.github/workflows/refresh-timetable.yml` уже настроен в исходном репозитории. Во вкладке **Actions → Refresh public timetable** можно вручную запустить **Run workflow** и проверить результат. Ветка `schedule-cache` содержит только `timetable.json`. Если делаешь fork, скопируй обе ветки, включи Actions и замени владельца/репозиторий в `SNAPSHOT_URL` конфигурации. GitHub может приостановить расписание workflow после длительной неактивности репозитория; включи его снова в Actions.

Если вход Wrangler через localhost не работает, используй `npx wrangler login --device --scopes account:read user:read workers_scripts:write d1:write offline_access` и введи показанный код на странице Cloudflare. Этот вариант не требует локального браузерного callback.

Для `workers.dev` скрипт настройки использует официальный параметр `ip_address`, подставив текущий IPv4 из системного DNS: DNS Telegram не всегда сразу видит новый домен. HTTPS и проверка сертификата остаются включёнными. Если адрес Cloudflare позже изменится и доставка прекратится, повтори `npm run webhook -- АДРЕС_WORKER`.
