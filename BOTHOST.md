# Запуск на Bothost

Подготовленный архив: `chuvsu-bot-bothost.zip`. В корне архива находятся `bot.py`, `schedule.py`, `requirements.txt` и `bothost.json`. Python 3.13 указан в конфигурации; библиотеки уже проверены локально на этой версии. Сам бот совместим с Python 3.11 и новее.

## Вариант с ZIP: Базовый или Pro

По [документации Bothost](https://bothost.ru/docs/upload-bot-archive), загрузка архива доступна только на Базовом и Pro. Функция пока работает на тестовой ноде; её доступность нужно проверить в панели.

1. Войди в аккаунт Bothost.
2. В профиле, в блоке «Интерфейс», включи **«Загрузка бота из архива»** и сохрани настройку.
3. В разделе «Мои боты» нажми **«Загрузить из архива»**.
4. Выбери `chuvsu-bot-bothost.zip`.
5. Название: например, **Расписание ИВТ-13-23**. Платформа: **Telegram**. Язык: **Python** или **Авто**. Главный файл: **bot.py**.
6. В поле токена вставь токен **этого бота** из BotFather. Bothost передаёт его коду как `BOT_TOKEN`. В архиве токена нет.
7. Если в форме есть опция веб-интерфейса / домена / webhook, оставь её выключенной: бот использует long polling.
8. Нажми **«Задеплоить»** и дождись завершения сборки.
9. Открой «Логи работы». При успешном запуске появится **«Бот @имя запущен»**.
10. Открой бота в Telegram → `/start` → **«Расписание на сегодня»**. Выбери подгруппу; для отправки в 07:00 нажми **«Ежедневная рассылка»**.

Не запускай одновременно копию на своём компьютере с тем же токеном. Telegram допускает одного получателя long polling; при конфликте программа остановится с ошибкой 409.

## Вариант через Git

По [FAQ Bothost](https://bothost.ru/docs/faq), бесплатный тариф поддерживает одного бота с long polling. Загрузка ZIP на нём недоступна; нужен Git-репозиторий.

1. Создай репозиторий на GitHub или GitLab и помести **содержимое** архива в корень репозитория. `.env` и `data/` в репозиторий не загружай.
2. В Bothost нажми **«Добавить бота»**.
3. Выбери Telegram и Python / Авто, вставь токен BotFather и URL репозитория. Укажи фактическую ветку репозитория.
4. Главный файл: `bot.py`. Веб-интерфейс / webhook не включай.
5. Создай бота, дождись сборки, проверь логи и кнопку в Telegram.

Для приватного репозитория потребуются дополнительные настройки доступа по [инструкции Bothost](https://bothost.ru/docs/git-repository-access). Публикация репозитория и выдача доступа к аккаунту выполняются отдельно.

На публичных страницах Bothost есть расхождения: [страница Telegram-хостинга](https://bothost.ru/telegram-bots) указывает спящий режим бесплатного плана, а [главная страница](https://bothost.ru/) предупреждает о потере данных бесплатного плана при перезапуске. Поэтому для ежедневной отправки точно в 07:00 и сохранения подписки проверяй фактические условия тарифа в панели. При сне контейнера бот не сможет вовремя отправить сообщение. Для постоянной работы нужен тариф без сна и с сохранением диска.

## Переменные и данные

В панели можно настроить:

```text
BOT_TOKEN=токен выбранного Telegram-бота
GROUP_ID=8075
BOT_TIMEZONE=Europe/Moscow
DAILY_TIME=07:00
ALLOWED_USER_IDS=
```

Для запуска достаточно `BOT_TOKEN`: остальные значения уже заданы в коде по умолчанию. `ALLOWED_USER_IDS` можно заполнить своим Telegram user ID, если доступ нужен только тебе. Это Telegram user ID, а не ID аккаунта Bothost.

После распаковки проекта в `/app` бот автоматически создаёт базу **`/app/data/bot.sqlite3`**. Здесь хранятся подгруппа, подписка и дата последней рассылки. На тарифе с постоянным хранилищем она должна сохраняться при обновлении; проверь это в условиях своего тарифа. Не удаляй папку `data` при обновлении.

Исходные инструкции: [переменные окружения](https://bothost.ru/docs/environment-variables), [главный файл](https://bothost.ru/docs/main-file-entrypoint), [хранение базы](https://bothost.ru/docs/database-storage), [библиотеки Python](https://bothost.ru/docs/installing-libraries).

## Если бот не запустился

- **Нужен токен Telegram** — проверь поле токена / переменную `BOT_TOKEN`.
- **Unauthorized / 401** — неверный или отозванный токен.
- **Conflict / 409** — останови другую копию этого бота.
- **Уже настроен webhook** — отключи прежний webhook для этого токена или используй нового бота. Программа сама существующий webhook не удаляет.
- **ModuleNotFoundError** — проверь, что `requirements.txt` в корне, и сделай новый деплой.
- **Сайт расписания недоступен** — проверь доступность `https://tt.chuvsu.ru` с сервера хостинга; программа не выдаёт сбой сайта за отсутствие пар.

Проверка расписания во встроенном терминале Bothost: `python bot.py --check`. Это не запускает вторую Telegram-копию.
